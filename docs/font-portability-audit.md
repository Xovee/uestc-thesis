# 字体与跨平台编译审计

## 目标

模板必须使用学校要求的宋体、黑体和Times New Roman，并尽可能让不同操作系统的用户
无需手动安装字体即可编译。默认使用仓库提供的字体；只有在字体文件不完整时，才回退到
系统安装的同名字体。字体条件均不满足时，XeLaTeX应停止编译，不得静默替换为其他字体。

核验日期为2026年8月31日。

## 分发依据

项目维护者确认已通过邮件分别取得Microsoft及Times New Roman字体提供方的明确许可，
可在本非盈利项目中使用并随项目向用户提供六个指定字体文件。授权沟通原件保存在公开
仓库之外，具体文件、SHA-256和权利边界记录在`THIRD_PARTY.md`。

六个文件的内部字体名称已经核验：

- `simsun.ttc`：SimSun和NSimSun；
- `simhei.ttf`：SimHei；
- `times.ttf`：Times New Roman Regular；
- `timesbd.ttf`：Times New Roman Bold；
- `timesi.ttf`：Times New Roman Italic；
- `timesbi.ttf`：Times New Roman Bold Italic。

它们的OS/2`fsType`均为`0x0008`，允许编辑式文档嵌入。字体本身不受项目LPPL许可覆盖，
本项目的分发许可也不自动授权提取、修改、单独分发或用于其他项目。

## 当前选择机制

`uestcthesis.cls`在加载时检查`fonts/`中的六个文件：

1. 六个文件全部存在时，从`fonts/`加载宋体、黑体和Times New Roman；
2. 只要缺少一个文件，就整体回退到系统字体`SimSun`、`SimHei`和
   `Times New Roman`；
3. 系统字体也不存在时，由fontspec报告缺失字体并停止编译。

该机制不依赖操作系统名称。仓库字体齐全时，Windows、macOS、Linux和其他能够运行
XeLaTeX的环境都走同一本地字体分支；用户删除字体文件后，仍可使用已经安装到系统中的
同名字体。六次文件存在性检查只发生在class加载阶段，对正文编译时间没有可感知影响。

中文正文使用宋体，中文无衬线文字和标题使用黑体；Times New Roman的常规、粗体、斜体
和粗斜体均显式映射到对应文件。数学字体保持TeX当前默认值，由用户按需要自行配置。

## 已完成验证

在Windows环境中使用同一份源码完成了两次完整编译：

1. 保留六个仓库字体文件，确认class选择仓库字体分支；
2. 在不包含`fonts/`的干净副本中编译，确认class选择系统字体分支。

两次编译均得到18页PDF。两个版本以96 dpi逐页渲染，18张页面图像的SHA-256全部相同；
`pdffonts`显示嵌入字体的名称、字体类型和子集状态一致。因此，当前Windows环境中的仓库
字体与系统字体不会产生可见版面差异。

字体文件还完成了以下检查：

- 六个文件均可由OpenType解析工具正常读取；
- 内部字体名称和字形类型与模板映射一致；
- 实际文件哈希与`THIRD_PARTY.md`及Release打包门禁一致；
- Release工具仅允许这六个确切文件进入发布包，文件变化会使打包失败。

## 尚待发布环境验证

- 在实际macOS和Linux环境中各完成一次完整编译；
- 在GitHub Actions的干净环境中使用仓库字体完成统一回归；
- 验证字体文件缺失且系统字体也不存在时的错误信息是否足够直接；
- 每次替换字体版本时重新确认许可、内部名称、哈希、嵌入标志和版面结果。

这些验证不要求改变当前字体顺序。除非测试发现具体问题，不再优先重构字体实现。
